## UPDATE — blocker fixed, `npm test` GREEN (commit `4471d98`)

The `blocked_cells_invalid` blocker is **fixed**. `npm test` passes end to end, `tsc
--noEmit` is clean, and both real maps convert.

**Root cause.** The variety cycle could relabel an obstacle into a type its authored
shape did not represent (`weave_left` -> `weave_right`, or `squat` -> a weave) while
leaving `blockedCells` / `gridMask` / `gameplayGeometry` describing the OLD type. Only
`squat` ever had its geometry rebuilt. The package validator checks that the blocked
cells actually imply the declared type, and correctly rejected the package.

**Offending obstacle on 3D44B:** a single-cell obstacle at grid column 2, authored
`weave_left`, relabelled `weave_right` by the cycle, geometry never moved.

**Fix.** Derive blocked cells and gameplay geometry from the TARGET type using
canonical shapes, never from the kept window's authored shape. The kept window still
supplies the timing and the authored source evidence.

**Derrick's decision, applied:** use the canonical full-wall shape per type, and
escalate a squat to the full weave wall when the cycle asks for it. Canonical shapes:

| type | geometry | blocked cells |
|---|---|---|
| `squat` | x0 y0 4x1 | 0,1,2,3 |
| `weave_left` | x2 y0 2x3 | 2,3,6,7,10,11 |
| `weave_right` | x0 y0 2x3 | 0,1,4,5,8,9 |

All three verified by execution: each geometry derives to its listed cells, and each
cell set implies its named type.

**Measured effect.** 3D44B goes from a hard rejection to 12 valid obstacles. 4858
changes by exactly one obstacle (a relabelled weave becomes the canonical full wall,
as approved). The geometry fix alone left the 952e map at 6 obstacles, 219
punches, 176 guards; the later clamp-timing fix raises punches to **228** (see
current table below). The frozen `task11` source-matrix oracle is byte-identical.

## Derrick's spec (confirmed, all four agreed)

1. Obstacle windows block punches — no punch authored while a weave/squat is up.
2. Clamp obstacle duration to a configurable max, default **3s**, Game Setup menu,
   reimport to apply, lock in later.
3. **4s cooldown** between obstacles; too-soon obstacles are DROPPED, never shifted.
4. Type cycling for variety on consecutive same-type obstacles.
5. **Only ONE obstacle at a time** — no squat+weave, no weave_left+weave_right.
6. **Drop `reachable` entirely.** Reduced beat count accepted. No post-obstacle
   recovery window this pass.

Pipeline order matters and is implemented: clamp → merge simultaneous → cycle →
cooldown → delete blocked punches LAST on the final obstacle set.
